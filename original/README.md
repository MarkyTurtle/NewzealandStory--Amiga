# The New Zealand Story (Ocean 1989, Amiga) - disassembly of the original

> This folder is **the original game**: sources that reassemble byte-identical to the original
> disk, its boot chain and copy protection worked out, and every file on the disk. The game on
> an **ordinary AmigaDOS disk** is in [`../enhanced`](../enhanced) - see the
> [top-level README](../README.md) and [`../BUILDING.md`](../BUILDING.md).

Conversion by Choice Software: code C. Gordon, graphics S. Connor.

Everything reassembles **byte-identical**:

```
vasmm68k_mot -Fbin -m68000 -no-opt -o main.bin nzs_main.s       ; sha1 74d3f9924c56270c5fc2a4231be035c9157851a1
vasmm68k_mot -Fbin -m68000 -no-opt -o loader.bin nzs_loader.s   ; sha1 853592064e08f7ee00a63c6a308e3d24777dec29
vasmm68k_mot -Fbin -m68000 -no-opt -o boot.bin nzs_boot.s       ; sha1 2b0cb038ff946d40f6942dc7e970bee83b3fa07f
vasmm68k_mot -Fbin -m68000 -no-opt -o boot2.bin nzs_boot2.s     ; sha1 cb653d3d40abff2489a51a13e55d315a316c847f
python3 tools/disk/pack.py pack main.bin main_packed.bin         ; sha1 068da7113d7db1746161301524898e843a58e787 (tracks 94-143)
```

`-no-opt` matters: the sources keep the original instruction sizes. `./build.sh` does all of it.

## Tools

| | |
|---|---|
| `tools/disasm/make.py` | Regenerates the sources from their configs (`main_cfg.py`, `loader_cfg.py`, `boot_cfg.py`, `boot2_cfg.py`: names, comments, headers, entry points, tables) with the engine `core.py`, then assembles each and checks it against the original |
| `tools/disasm/core.py` | The engine: traces the code from the entry points (capstone), checks with vasm that every instruction reassembles to its own bytes (an instruction vasm encodes differently - one, `move.w #$FF,ccr` stored as `$FFFF` - is written as `dc.w` with the instruction as a comment), names labels and hardware registers, and writes the source. A program is segments of (file range, run address): the first blocks of the main program and the game loader run at a different address from where they are loaded, and each segment gets its own `org` in one section, so the labels carry run addresses while vasm writes the bytes contiguously |
| `tools/disasm/tvd.py` | Decrypts trace-vector-encrypted code statically (`docs/BOOT.md`) |
| `tools/protemu/` | The protection run in a 68000 emulator (Musashi, with the trace exception and address errors): `build.sh`, `harness.c`, `run_protection.sh` |
| `tools/disk/extract_files.py` | Extracts the files from the game-tracks ADF, checked against the known sizes and the captured unpacked program |
| `tools/disk/ipf_extract.py`, `build_dump.sh`, `dump.cpp`, `ados.py`, `mfm.py` | Read the original IPF (via capsimg): the protection loader and the Copylock track |
| `tools/disk/pack.py` | The main program's packer / unpacker, byte-identical to the original's |
| `tools/disk/game_tracks.py` | The tracks the game reads while it runs (level data), from its tables |
| `tools/screen.py` | Renders the display from a memory image by following the copper list |
| `tools/dis.py` | A quick capstone listing of any address range |

### How the disassembly is generated

`main_cfg.py` gives the entry points (`Relocate`, the jump table at `$400`, the game at `$4000`),
the tables of code pointers (the monitor's commands, its disassembler's), the sound driver's
self-relative command table, the object field that holds code pointers (`$18`: `move.l
#handler,$18(aN)`), the error trap that never returns (`trap #14` with its message after it), and
names. The tracer follows the code from there and also detects `jmp n(pc,dN.w)` into a list of
`bra.w`. A sweep then looks for code nothing traced reaches - routines straight after an
`rts`/`bra`/`jmp` - and keeps them only if every path decodes as 68000 code, overlaps nothing and
reassembles to its own bytes; they are marked `; (no references found: found by the code
sweep)`, to be confirmed. About 33 KB of code is identified so far below `$F340` (the sound
samples follow), the rest written as data: some code is still only reached through the animation
scripts (object field `$14`, whose commands embed code pointers - the `jsr (a0)` at `$B490`) and
other indirect jumps listed by the tracer.

## How the program runs

1. The track 90 loader leaves the program at `$400` and jumps there, with `d0 = a0 = $400`.
2. `$400: bra.w Relocate` moves block 1 down 4 bytes (file `$404-$3213` to `$400-$320F`) and
   jumps to `$400`: a jump table - `Init`, key test, joystick, `TrackRead`, `TrackWrite`, get key.
3. `Init` (`$55A`) enters supervisor mode (a privilege violation into the next instruction), sets
   the stack below `$400`, points every exception vector at `$158C` (keeping the trace vector),
   installs `ErrorTrap` as `trap #14`, turns both drives' motors off (`$9DA`) and goes on into the
   system layer's start-up (`$62C`), which also calls `$158C`. Block 1 holds a debug monitor -
   commands `MRWDJGV`, `X`, `H`, `N`, `S`, `Z` and others (keys at `$6BE`, routines at `$6D2`),
   with a 68000 disassembler and track read / write; its `G` command defaults to `GameStart`
   (`$4000`), where the game proper begins. The exact path from `Init` to `$4000` is still to be
   followed.
4. The game is interrupt driven: level 3 (vertical blank, `Level3_VBL`, `$BDD8`) resets CIA-B's
   TOD each frame, reads the joystick through the jump table and calls the frame code (`$E80C`);
   level 6 (CIA-B, `Level6_CIAB`, `$BE8A`) times a mid-screen change with the TOD alarm and
   counts down timer B; level 2 (`Level2_Ports`, `$12D8`) is the keyboard. The sound driver is
   around `$EFD0` (it uses the audio interrupts), with sample data around `$F500` and `$12500`.
5. At the start of each level `LoadTracks` (`$55BA`) reads the level's tracks through the jump
   table's `TrackRead` - always from DF0, at fixed track numbers (`disk/DISKMAP.md`) - and
   `UnpackLevel` unpacks them in place; a disk that fails 5 times gives the "fatal disk error"
   screen. (On the AmigaDOS disk, `TrackRead` is replaced: `../enhanced/src/diskload.s`.)
